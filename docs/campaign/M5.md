# M5: Python and circuit workflows

`maturin build --release` builds the isolated PyO3 0.29.0 bridge in
`bindings/python`. The default native workspace has no Python dependency.
`crn_craft.simulate`, `fsp`, `check` and `analyze` consume exact bytes or explicitly
serialized dictionaries. `run_spec` binds a run to those exact model bytes.
The GIL is released during numerical execution. Incomplete SSA results retain
termination and withhold statistics, just as the CLI does.

`crn_craft.observables.oscillation` reports a trajectory-wise spectral/autocorrelation
diagnostic on a checked uniform grid after burn-in. It labels short-horizon evidence
ambiguous. `sampled_first_passage` preserves right censoring and reports lower/upper
restricted-mean bounds from the saved grid; it does not invent event-time observations.

`validation/check_python.py` proves CLI/binding and 1/2/8-thread identity, exercises
strict parsing, synthetic development/held-out positive and negative controls,
censoring, and 16 native three-gene paths with disjoint development/validation seeds.
All seven grouped checks pass; normal/-O reports agree. The original circuit-study
source was not supplied, so this is explicitly a synthetic fixed-topology example.
The small controls do not establish general 95%/99% biological detection rates.
