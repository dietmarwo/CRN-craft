# M6: existing job SDK and optimization studies

The separate `integrations/jobs` workspace pinned fcmaes-rust 583f33a and its
actual optimization-job-api revision 602d31a for M6. The then-current runner tested
is optimization-jobs cc6b03d. It now pins fcmaes-rust f764a75 and
optimization-jobs 12f9d57, which change only documentation and the pin
between them; the rerun against a runner built at 12f9d57
([jobs-pin-12f9d57.json](../../validation/campaign/jobs-pin-12f9d57.json))
matches the review report except for its protocol pins. The default numerical workspace has no job SDK,
optimizer or Rayon dependency. No new envelope or lifecycle was invented.

The native worker registers `app.crn.fit-moments` and `app.crn.circuit-score`
with existing retry, surrogate and evaluate profiles. Inputs are hashed model
and fit-data files; rate coordinates are natural logarithms. Fit loss uses
normalized mean/variance time-course residuals, averaged over seeds. Circuit score adds an
amplitude-floor penalty to the fixed-topology temporal-shape loss: the mean over
all replicate paths of 1/(1+variance) of the required, named `amplitude_species`
over save times after `burn_in` (default 0, so the initial state never counts).
It is an explicit synthetic calibration objective, not a biological oscillation
certificate. Actual three-gene example data and model are included under
integrations/jobs/examples.

Problem version 2 (review fix) changes the contract. `seed_set` is required, with no
default, for both problems; circuit-score requires `amplitude_species`. The penalty
was a sum over paths and grew with the replicate count; it was hard-wired to species
index 0 and included t=0. Version 1 jobs must add these parameters. The fit-data and
model schemas are unchanged.

Every candidate uses the same declared seed_set and replicate streams; the
point-derived SDK seed is intentionally unused. Incomplete work fails the
objective. A checkpoint bridges SDK cancellation/deadline to the event loop,
and the numerical worker count is at most the supplied thread allowance.

`validation/check_jobs.py` executes the real worker through optimization-run:
17 optimization/evaluate jobs plus a shell-free command job, an active deadline,
32-call equal-budget BiteOpt versus surrogate at 8 and 64 replicates, SDK rechecks,
separate disjoint-seed best-point validation jobs, 1/8-thread equality, explicit
failure accounting and ring/broken-ring held-out evaluations. This is a small pilot, not
a ranking of search algorithms or a guarantee of fit identifiability.

Before the review fix it never asserted evaluation results. Report
jobs-validation/0.2 now asserts several properties. Every finite evaluate objective
(14 values, both problems) equals an independent Python recomputation through the
binding (same cached SSA, seeds and streams; loss, seed mean and amplitude penalty
recomputed) within 1e-12 relative; the measured difference was 0. A repeated job is
identical. Reversed points give reversed objectives. Results follow request order.
The true rates score below offset rates on the search and held-out seed sets. The ring
scores below the broken ring. Jobs missing `seed_set` or `amplitude_species` fail
validation. The topology jobs use m2, not species 0. The main report holds only
reproducible content and is identical under `python -O`. Runner responses and
native manifests, with paths and timings, go to a sibling `.raw.json`. Worker mutants
that sum the penalty over paths, hard-code species 0, include t=0, default the seed
set or sum over seeds each fail the check.

Early driver failures (a discovery example assumed per model/profile, and a
wrong surrogate budget field) are retained. The final driver uses the actual
SDK discovery shapes and `evaluations` field. Initial clippy suggestions were fixed.

Build: `cargo build --release --locked --manifest-path integrations/jobs/Cargo.toml`.
Register the resulting crn-job-worker with the existing runner, or use its
`describe`, `validate` and `execute` commands. Publishing remains owner-controlled.
