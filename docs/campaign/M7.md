# M7: optional BDF, sensitivities, fitting and conservative screening

`integrations/diffsol` pins diffsol 0.18.0, using native closures and Nalgebra BDF,
without DiffSL/LLVM. It has its own lockfile and Rust 1.89 requirement; the default
core remains Rust 1.85. `crn-diffsol MODEL REQUEST` returns ODE result/0.1, including
raw-parameter forward sensitivities. New core Kinetics evaluates analytic state
and parameter Jacobians, checked against independent central differences.

The count-kinetic convention is macroscopic c*product(y^order/order!), not the
nonlinear stochastic mean. Production-only Hill and substrate-consuming MM laws
have explicit smooth extensions; discrete gates without a smooth extension are
rejected. Limits are 64 species, 32 parameters, 256 reactions and 10000 requested times.

State-domain rule (review fix; it replaces "negative states fail"). The core
Kinetics still rejects negative states. crn-diffsol evaluates rates and parameter
derivatives at max(y, 0) and uses the Jacobian of that extension, in which a negative
component has no effect. Every consuming reaction has zero rate at zero
reactant, so the exact trajectory from non-negative counts never leaves the
non-negative orthant and is unchanged. Only BDF predictor/Newton trial states,
which formerly aborted plain decays for T >= 40, see the extension. Accepted states
and reported values must stay within one solver error weight of the species
scale: a value below -(atol + rtol * m_i), where m_i is the largest value of
species i seen, is CRN-E080. Crossings between accepted steps are located by
diffsol root functions; reported values are checked again and never clipped.
Requests that succeeded before return byte-identical results.

A declared population_limit is a safety stop as in the SSA: a value above
limit + atol + rtol * limit, between steps or at a save time, is CRN-E044 with no
output. Any kinetics diagnostic (for example a singular Hill derivative) is reported
instead of the solver failure it causes. Solver panics (for example times near
f64::MAX) are caught and reported as CRN-E080 with exit 1; every failure is one
JSON line on stderr. Oscillators over very long horizons can still exhaust the BDF
nonlinear-failure limit at loose tolerances (as before), and there is no step or
wall-time budget.

The predeclared 16 BDF/analytic/DOP853/sensitivity comparisons pass. The review fix
keeps them unchanged and adds 34 rows (50 in total; same 1e-5 value and 1e-4
sensitivity thresholds) using `integrations/diffsol/fixtures`:
dimerization 2A -> B (A(1) = 50 under c*A^2/2!, with analytic values and dA/dc),
Hill activation and repression against closed forms, a moving regulator with an
X + 2Y binding (DOP853 and relative-step central differences for every parameter),
decay through zero on three horizons against exp(-t) within atol + rtol * A0,
enzyme T=1000 and reduced MM T=200 with conservation, and the failure contract
(population limit at and between save times, f64::MAX time, retained kinetics
diagnostic). Rust tests in `integrations/diffsol/tests` add closed forms and
analytic Jacobians at three distinct states per model. Mutants of the factorial
convention, Jacobian species index, Hill activation sign, activation/repression
swap, activation value, transposed Jacobian product and unclamped trial states
each fail both the Rust tests and check_ode. Before the fix, the convention
mutant passed all 16 rows, and the species-index mutant passed the core test.

The synthetic `examples/circuit/fit_ode.py` uses pinned fcmaes-rust 0.2.1 and SQP-craft
0.17.0: 64 BiteOpt calls, explicit best-point start, derivative checks, native forward
sensitivities and an independent analytic re-evaluation. Loss falls from 0.5901 to
4.97e-20. Report global-local-fit/0.2 gates on the SQP derivative report and
asserts that the native sensitivity order equals the coordinate order (birth,
death). It also checks the native gradient at the initial and global-best points
against the closed form (1e-6) and native central differences (1e-4). With these
checks there are 105 native propagations. Wall-clock fields go to a sibling
`.timing.json`, so the report is identical under `python -O`. A gradient scaled by
1.5 converged to 2e-18 and passed the old gate; it now fails.

`screen.py` never removes a topology based on its deterministic trajectory.
Both the three-gene ring and the paper-defined Vilar control (delta_R=0.05) receive
eight held-out SSA paths. No universal detection accuracy or noise-driven-oscillation
proof is inferred. The nonzero-allocation guarantee, rather than a hard ODE filter,
prevents deterministic screening false negatives by construction.

The original gate was constant true. Report screen-study/0.2 declares five criteria.
Every topology gets exactly eight completed, diagnosed SSA paths. Every ODE solve
completes. No topology is rejected by its ODE. The ring's ODE (screened species m1,
named) is oscillatory. At least one ODE-non-oscillatory topology still gets the full
allocation. The gate is also applied to five perturbed copies of the measured rows,
and each must fail. The default horizon is 400: it leaves about four ~45-unit ring
periods after the 50% burn-in. At the earlier horizon of 200 the ring ODE is
ambiguous, and that run fails the gate; it is retained as the failing case. At 400
the Vilar ODE is non-oscillatory, and all eight of its SSA paths are classified
non-oscillatory for A as well. Source: Vilar,
Kueh, Barkai & Leibler (2002), https://pubmed.ncbi.nlm.nih.gov/11972055/.
The 16 reaction equations/parameter values are mathematical model definitions;
no simulator source was copied.

The first fit driver used `activeset`; the installed package requires `active-set`.
The failed log is kept. The default core's derivative tests and optional clippy pass.
