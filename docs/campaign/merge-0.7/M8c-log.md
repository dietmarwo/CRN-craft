## Compiled-loop cache after an upgrade

The cache key is the SHA-256 of `fingerprint`, `version`, `rustc`,
`target`, `environment`, `driver` (hash of the driver files) and `source`
(`"crates.io"` or the checkout path and digest); the entry folder is the
key's first 32 hex digits, and an entry is reused only if its `loop.json`
holds the same key. After M8c the `fingerprint` of every model changes (the
template text changed), and so does `driver`; for checkout builds the
`source` digest changes too, and at release `version` goes from 0.6.0 to
0.7.0. Every loop cached by 0.6.0 is therefore rebuilt once, into a new
entry, and cached again from then on. Old entries are not reused or
removed: they stay in the cache directory, and so do the old artifacts in
the shared target directory, until the user deletes the directory.

Measured with `/home/claude/m07/m8c/upgrade_probe.py` and one cache
directory for both phases: the base wheel and checkout (`21f71b8`), then
the M8c wheel and checkout. Three models: the mtDNA takeover model with
trackers and an event log, the builder SIR with string rates and inverse
waits, and the `model/1.0` higher-order fixture with quantiles under
`run/1.0`.

| Model | First call after upgrade | Second call | Key fields that changed | Result bytes (metadata and 10 record columns) before vs. after |
| --- | --- | --- | --- | --- |

| SIR, string rates | built, new entry | cached | same | identical |

## What a crates.io build needs

Without `source=` or `CRN_CRAFT_SOURCE`, `compile_loop` writes:

```toml
[dependencies]
crn-craft = { version = "=0.7.0" }
serde_json = "1"
```

with `0.7.0` being `crn_craft._native.__version__`, the version of the
binding crate `crn-craft-python`. For this to build after the release:

- `crn-craft` 0.7.0 must be on crates.io, with `src/rules/` (its
  `include = ["src/**", ...]` covers it). `crn-craft-rules` is no longer
  needed by `compile_loop`.
- The wheel version and the `crn-craft` crate version must be equal (both
  set in M11): the requirement is exact, since the loop and driver are tied
  to the engine the extension was built from.
- `crn_craft::rules` must keep exporting what generated code and the
  driver call: `RulesLoop`, `RulesKernel`, `LoopHost`, `LoopHalt`,
  `combination_rate`, the hidden `libm`, `Control`, `prepare`,
  `execute_with_rules_loop`, `Record`, `RulesResult`, `Termination`
  (M8b must not remove or rename them).

Tested here as far as possible without a release: `cargo package -p
crn-craft --locked --no-verify` packed 64 files, including all 28 files of
`src/rules/`. With `CRN_CRAFT_SOURCE` unset, `compile_loop` wrote the
crates.io manifest above (version `=0.6.0` on this branch), and a
`[patch.crates-io]` entry in the cache directory's `.cargo/config.toml`
pointed `crn-craft` at the unpacked archive. Cargo compiled
`crn-craft v0.6.0` from the archive, locked serde 1.0.229 and serde_json
1.0.154 (the crate's exact pins; "Locking 34 packages to latest Rust 1.85
compatible versions"), the self-check passed, and the takeover result was
byte-identical to the checkout build (`/home/claude/m07/m8c/published_probe.py`,
`/home/claude/m07/m8c/published-probe.json`).

Untested: downloading `crn-craft` 0.7.0 from crates.io (it does not exist
yet), the `0.7.0` version string itself, resolution against the live index

## Migration notes

- Generated kernels and loops (`generate_rules_kernel`,
  `generate_rules_loop`, Python `loop_source`) name `crn_craft::rules::`. A
  Rust project that compiles generated code must depend on `crn-craft`
  directly; a dependency on `crn-craft-rules` alone no longer suffices.
  Regenerate code generated by 0.6.0.
- `compile_loop` builds against `crn-craft` at exactly the installed
  version. `source=` and `CRN_CRAFT_SOURCE` need a checkout with
  `crates/crn-craft/Cargo.toml`. Cached loops of 0.6.0 are rebuilt once on
  first use; their results stay byte-identical. Delete the cache directory
  (`~/.cache/crn-craft/rules-loops` on Linux) to reclaim the space of old
  entries.
- The rules tests, stored requests and generated fixtures are in
  `crates/crn-craft/tests/`.
