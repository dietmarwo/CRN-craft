# Closing the JumpProcesses.jl gap: predeclared protocol

Date: 2 November 2026. Base: the imported exact-SSA acceleration patch
(commit 3184f65 on `ssa-acceleration`, GitHub base `baed0e4`). This file is
committed before any iteration is measured.

## Why CRN-craft is still slower

The comparison in [comparison-catalyst-jumpprocesses.md](../comparison-catalyst-jumpprocesses.md)
measured Julia's fastest aggregator 1.54–2.39× faster than the fastest CRN
option on W1–W7 (geometric mean 2.02×). Reading JumpProcesses.jl 10.0.1, the
Catalyst-generated W1–W7 code and callgrind profiles of the imported engine
(`examples/bench_ssa.rs`, this host) separates the gap into:

| Cause | Evidence (self instructions unless stated) | Julia |
|---|---|---|
| Cooperative stop polling per random word and per loop | `Poller::poll` 6–12% on W1, W2, W3, W6; it is an out-of-line call | No cancellation checks |
| ChaCha8 on the SSE2 fallback | `rand_chacha` built without `std`, so `ppv-lite86` never dispatches to AVX2; 6% on W2 | Xoshiro256++ |
| Hill laws through `log1p`/`exp`/`log` | `CompiledRate::evaluate` + software `libm` ≈ 20% on W3 | Closed form `basal + v/(1+(x/K)^n)` |
| Strict ordered prefix sums with per-channel loss checks | `resume_total` 20–25% on W3 cached | Incremental `sum_rate += new - old`, no drift or resolution checks |
| DirectCR tree bookkeeping | `RateTree::set` 18% on W2 (sum, minimum and loss flag per level) | O(1) incremental group sums |
| DirectCR envelope recomputation and draws | `Composition::sample` 14% on W2: weights with divisions every attempt, three words per attempt | Group chosen by actual sums; one draw per rejection attempt, reusing its fractional part |
| RSSACR bound refresh | `Bounds::refresh` with inlined tree updates ≈ 40% of W6 path instructions | Bracket updates without checked tree rebuilds |

Some of the remaining difference is a deliberate policy: CRN-craft checks every
positive channel against the 53-bit selection resolution, rejects lost
increments and rebuilds totals without accumulated drift; Julia does not. This
campaign keeps those guarantees. It removes overhead around them and changes
random paths only where a separate statistical gate is passed.

## Iterations

Each iteration is a separate commit with tests and paired timing; a rejected
iteration is reverted and its evidence kept.

| ID | Change | Class | Target rows |
|---|---|---|---|
| A01 | Inline the poller's fast path; new engines poll once per loop iteration, per rejection attempt and every 64 inner steps instead of per random word | exact | all new methods; legacy where inlining applies |
| A02 | Enable runtime AVX2 dispatch in ChaCha8 (`rand_chacha/std`, no new crate) | exact (identical stream) | all |
| A03 | Exact memo of one-variable Hill rates by integer regulator count (lazily filled, shared, bounded) | exact (same function values) | W3 all methods |
| A04 | RSSACR mass-action bounds reuse the lower-corner value as the minimum positive rate when no gate applies (one evaluation fewer) | exact numbers; fewer counted evaluations | W4–W7 `rssa_cr` |
| A05 | Cache the composition envelope prefix; recompute only when group membership changes | exact | `direct_cr`, `rssa_cr` |
| A06 | Cheaper `RateTree` bookkeeping (separate sum/minimum/flag storage; same decisions) | exact | `direct_cr`, `sorting_direct`, `rssa_cr` |
| A07 | Branch-reduced ordered prefix sums; the checked loop reruns only to report the first failing channel | exact | cached Direct, legacy cached |
| A08 | One 64-bit word supplies both member index and acceptance in composition rejection | path-changing | `direct_cr`, `rssa_cr` |
| A09+ | Further profile-driven items after A01–A08, declared in the log before measuring | either | declared then |

## Acceptance rules (fixed now)

Measurement: `validation/measure_julia_gap.py` drives release
`bench_ssa` binaries built from the parent and candidate commits. Seven
workloads (W1–W4: 64 paths to t=100; W5–W7: 16 paths to t=20; seed 4242; one
thread) × five methods (legacy cached/inverse, and `cached_direct`,
`direct_cr`, `sorting_direct`, `rssa_cr` with Ziggurat waits). Five
alternating paired rounds, three timed repeats after one warm-up; the paired
ratio is parent median / candidate median per round. No build or validation
runs during timing. No observations are dropped.

- **Exact iterations** must give identical numerical result digests on all 35
  rows (the digest of the result with work counters removed) and pass the full
  Rust suite. Work counters may change only where the iteration does less
  counted work, and the change must be explained in the log. Path-changing iterations must additionally pass
  `check_alternative_ssa.py` (independent laws and CME oracles, 210
  comparisons) under normal and `-O` Python and keep worker-count replay.
- **Speed**: median paired speedup ≥ 1.03 on the declared target rows, and at
  least four of five rounds > 1 on each target row.
- **No regression**: no other row may have median paired speedup < 0.97. A row
  that fails only this rule may be re-measured once with five new rounds; the
  decision then uses all ten rounds. No other re-measurement is allowed.
- Legacy archives, RNG vectors, schemas and Direct/cached byte identity must not
  change.

## Gap estimate without Julia on this host

Julia's package hosts are blocked by this session's network policy, so the
final comparison is a **projection**, not a measurement: for each workload and
method, the comparison report's CRN prepared median (AMD EPYC host) is
multiplied by the cumulative paired speedup measured here, and the fastest
projected CRN option is divided by Julia's fastest measured median. This
assumes relative speedups transfer between hosts and between the Rust and
prepared-Python boundaries. The campaign target is a projected geometric-mean
gap ≤ 1.4× (from 2.02×); missing it is reported, not hidden. A direct rerun
with `validation/compare_julia_accelerated.py` remains the authoritative check.

Workload IDs W5–W7 here are the acceleration report's larger networks, not the
P11–P20 performance campaign's W5–W7.

## Corrections made before any iteration was accepted

- The first profile was collected over the whole `bench_ssa` process, so
  allocations and diagnostic formatting from model validation appeared in the
  W6 profile. Profiles restricted to `ssa::path` show no allocation in the event
  loop. A04 was redefined accordingly before its measurement.
- The digest rule was clarified to compare numbers separately from work
  counters, so an exact iteration that skips a redundant evaluation is not
  mistaken for a path change.
- The first A01 timing run was stopped after 12 rows because review jobs were
  running benchmarks on the same two vCPUs. Its partial output is kept in the
  implementation log and is not used for a decision.
- Timing every iteration pair separately would take about 40 minutes per
  iteration on this host, mostly in the W4 Direct-family rows. Before any
  decision, the harness gained a `chain` mode: every commit's binary runs in
  each of the five rounds, in an order rotated and reversed between rounds,
  and each commit is paired with its parent within those rounds. Thresholds,
  repeats, rounds and rows are unchanged. The stopped pairwise A01 run is kept
  as partial evidence and not used for the decision.
- The engine and bounds reviews (run in parallel with A01–A07) proposed a
  batched ancestor rebuild and a gentler buffer-shrinking policy. They are
  added as A09 and A10, exact iterations with the same target rows as A06 and
  A05 respectively, declared here before their measurement.
