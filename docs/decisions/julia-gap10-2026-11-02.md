Date: 2 November 2026 (America/La_Paz). Base: GitHub main add6cca, merge
of PR #7, freshly fetched. The prior campaign is already included; this is a
new C01–C10 campaign. The attached gap log is context, not a numerical oracle.

## Goals and invariants

Aim to reduce same-host warm CRN/fastest-Julia time toward 1.0, with geometric
mean <=1.25 as an aspirational target, not an acceptance requirement. Rerun
actual pinned Julia 1.13.3 / Catalyst 17 / JumpProcesses 10.0.1; do not project
speedups across hosts. Keep all failures, rejected candidates and raw timings.
No remote push, package publication or branch deletion is authorized.

Legacy results/RNG streams and alternative sampler v2 remain unchanged. All ten
candidates are intended to preserve paths and checked numerical decisions.
Counted propensity evaluations may fall when an evaluation is actually avoided;
report this separately. Preserve all availability gates, transactional updates,
precision/loss checks, integer-box bounds, absorption, sampling budgets and
bounded cooperative stops. C02 may delay a random-word stop check by at most
63 words; outer/rejection/bound-loop checks still operate. Stops are outside
fixed-work identity. No new request/result/sampler shape is planned.

## Per-iteration checks and measurement

Build the parent and candidate release `bench_ssa` binaries into separate files.
Run the whole Rust workspace release suite with --locked for each candidate.
Check all 35 existing workload/method rows with four paths, full horizons and
fixed seed 4242, comparing numerical digests (work fields excluded). Results
must complete and replay; legacy full digests must also remain unchanged.

Timing uses these eleven representative rows, all on one numerical worker:
W1 legacy_cached/inverse; W2 direct_cr/ziggurat and sorting_direct/ziggurat;
W3 legacy_cached/inverse and sorting_direct/ziggurat;
W4 cached_direct/ziggurat and rssa_cr/ziggurat;
W5 direct_cr/ziggurat and rssa_cr/ziggurat;
W6 and W7 rssa_cr/ziggurat. Original horizons/path counts remain (W1–4:
64 paths,t100; W5–7:16 paths,t20). Each subprocess warms once, then returns
two timed repeats. Five paired rounds alternate parent/candidate ordering and
rotate row order. No build, validation or other heavy task runs during timing.
Every observation is retained.

Keep a sound candidate if the geometric mean of target-row paired median
speedups is >=1.02, at least four of five target aggregate rounds improve,
and the geometric mean across all eleven guard rows is >=0.995. Any individual
guard row below 0.95 gets exactly one additional five-pair check; its ten-round
median must then be >=0.95, otherwise reject. No other remeasurement or threshold
change. These aggregate targets differ deliberately from the prior campaign's
per-target-row rule; this protocol is fixed before this campaign's measurements.
Instruction counters are unavailable here (perf/valgrind absent); use exact
algorithmic operation tests, work counters and measured timings, not invented
instruction/cycle attributions. Compilation costs are recorded separately.
